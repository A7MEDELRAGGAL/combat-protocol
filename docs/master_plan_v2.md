# Combat Protocol — خطة التطوير الشاملة v2

**التاريخ:** 26 أكتوبر 2026
**الإصدار الحالي:** `1.9.0`
**الهدف:** الانتقال من Prototype محلي مُتقن إلى لعبة FPS كاملة: حركة سلسة، أنميشن حقيقي، شخصيات وأسلحة بمستوى بصري أعلى، باتل رويال كامل، مالتي بلاير، نظام لفلات، وأطوار متعددة.

---

## 0. القواعد الحاكمة

1. **لا ندّعي ميزة قبل وجود كود + اختبار + دليل مرئي.** كل بند في الخطة له «معيار قبول» قابل للقياس.
2. **لا أصول من أي لعبة أخرى.** كل شيء procedural أو مولّد داخلياً.
3. **كل ميزة تمر بدورة:** عقد بيانات → منطق نقي → اختبار وحدة → ربط واجهة → فحص متصفح → لقطة.
4. **الأداء ميزة:** 60 FPS على جهاز متوسط، 30 FPS حد أدنى في BR.
5. **الترتيب لا يُقفز:** لا مالتي بلاير قبل تثبيت الحركة والقتال محلياً.

## 2. شاشة المراكز والقتلات (Placement)

### المنفذ الآن
- خلية «المركز» في شاشة النتائج.
- `computePlacement()`: الفوز = 1، الموت = (عدد الأحياء + 1) محدوداً بحجم اللوبي.
- القتلات تُعرض بالفعل، ويُضاف إليها الهيدشوتس في الـtelemetry.

### المتبقي (المرحلة P1 — 3 أيام)
1. جدول ترتيب مصغّر (Top 5) يظهر أسماء البوتات وترتيبها.
2. شارة «المركز الأول» / «أفضل 10» / «أفضل 25» بلون مختلف.
3. مكافأة XP متدرجة حسب المركز: `xp = 250 - (placement - 1) × 10` بحد أدنى 50.
4. انتقال سلس: Debrief → «مهمة جديدة» يحفظ آخر مركز.

**معيار القبول:** إنهاء مباراة BR والموت في المركز الرابع → تظهر «4 / 20» وXP محسوب بالمعادلة أعلاه، مع اختبار وحدة يغطي 1 / 4 / 20.

## 3. المالتي بلاير (المرحلة الأكبر)

### 3.1 البنية

```text
Client (Three.js)
  → WebSocket (binary)
  → Gateway (Node/uWebSockets)
  → Room Manager
      ├─ Simulation 20Hz (authoritative)
      ├─ Snapshot 10Hz
      ├─ Lag compensation buffer 500ms
      └─ Anti-cheat validation
```

| القرار | الاختيار | السبب |
|---|---|---|
| النقل | WebSocket binary | أقل overhead من JSON بـ 60-70% |
| Tick | 20Hz | كافٍ لـFPS سريع بدون استهلاك bandwidth |
| المصادقة | توكن قصير العمر + session id | يمنع انتحال الهوية |
| الحركة | Client prediction + server reconciliation | إحساس فوري بلا غش |
| الرمي | Server timestamp + rewind | «أطلقت قبله» يُحل بشكل عادل |
| الغرف | Room per match، تُغلق فوراً عند الفراغ | تكلفة سيرفر منخفضة |

### 3.2 بروتوكول الرسائل (schema)

| الرسالة | الاتجاه | الحقول |
|---|---|---|
| `join` | C→S | `name, loadout, token` |
| `input` | C→S | `seq, dt, move{x,z}, yaw, pitch, buttons` |
| `snapshot` | S→C | `tick, players[], projectiles[], zone, score` |
| `hit` | C→S | `seq, targetId, hitPoint, weaponId` |
| `respawn` | S→C | `playerId, position` |
| `matchEnd` | S→C | `placement[], stats[]` |

### 3.3 مراحل التنفيذ

| المرحلة | المدة | معيار القبول |
|---|---|---|
| MP-1: غرفة محلية بسيرفر واحد | 2 أسابيع | لاعبان يتحركان ويريان بعضهما، tick مستقر |
| MP-2: ضرر وذخيرة على السيرفر | أسبوعان | لا يمكن للعميل إحداث ضرر غير مصرح |
| MP-3: lag compensation | أسبوع | p95 < 120ms داخل نفس المنطقة |
| MP-4: 8 لاعبين + إعادة اتصال | أسبوعان | انقطاع 10 ثوانٍ ثم عودة بلا فقدان حالة |
| MP-5: 20 لاعباً + مكافحة غش | 3 أسابيع | اختبار حِمل موثق p50/p95 |

**معيار القبول النهائي:** لاعبان حقيقيان يقتلان بعضهما في TDM، والسيرفر هو مصدر الحقيقة للضرر والذخيرة والنتيجة.

**المخاطر:** تعقيد reconciliation، NAT، تكلفة الاستضافة، الغش. التخفيف: ابدأ بـ2 لاعبين، ولا تُعلن «مالتي بلاير» قبل MP-3.

## 4. الإنزال المظلي (Parachute)

### التصميم
1. طائرة تمر بخط عشوائي على ارتفاع 120م، سرعة 40م/ث.
2. Player يضغط `Space` للقفز في أي لحظة.
3. مراحل الطيران:
   - **Freefall:** جاذبية 9.8، سقف سرعة 55م/ث، تحكم أفقي محدود.
   - **Parachute:** يُفتح تلقائياً عند 40م أو يدوياً، سرعة هبوط 6م/ث، تحكم كامل.
4. الهبوط يفرّغ الغنائم حول نقطة الهبوط (3-5 صناديق).

### المعادلات
```
v_y = min(v_terminal, v_y + g*dt)
v_xz = lerp(v_xz, input * maxSpeed, drag*dt)
```

**معيار القبول:** تبدأ مباراة BR من الطائرة، تقفز، تهبط، وتجد 3 صناديق على الأقل حولك، بدون تعليق أو سقوط في الأرض.

**المدة:** أسبوع.

## 5. Revive / Downed

### القواعد
- عند وصول الصحة لـ0 في السكواد: تدخل حالة **Downed** (30 ثانية، سحب بطيء 1م/ث، لا سلاح).
- الزميل يضغط `E` لمدة 4 ثوانٍ → revive بنسبة 40% صحة.
- في السولو: لا Downed، موت مباشر (كما الآن).
- «Thirst»: ضرر إضافي بعد 30 ثانية إن لم تُنقذ.

**معيار القبول:** لاعب يسقط، زميله يرفعه، ويعود للقتال؛ وإن انتهى العدّاد يموت. اختبار وحدة يغطي الحالات الأربع (downed/revived/thirst/dead).

**المدة:** أسبوعان (يحتاج سكواد أولاً).

## 6. الأنميشن — المشي والجري والكراوتش والريلود

### 6.1 الهيكل العظمي (Rig)

الانتقال من الصناديق إلى **هيكل مبني بالكود** (procedural rig) بدون أصول خارجية:

```text
Root
├─ Hips
│  ├─ Spine → Chest → Neck → Head
│  ├─ UpperArm.L/R → LowerArm.L/R → Hand.L/R
│  └─ UpperLeg.L/R → LowerLeg.L/R → Foot.L/R
```

- 17 عظمة، كل عظمة `Group` بمحور دوران مستقل.
- الموديل نفسه يبقى boxes/cylinders لكن **مربوط بالعظام**، فيتحرك كجسم واحد.

### 6.2 الحالات والمنحنيات

| الحالة | الحركة | المدة |
|---|---|---|
| Idle | تنفّس صدر ±2°، رأس ±1° | 3s loop |
| Walk | فخذ ±28°، ركبة ±35°، ذراع معاكس ±20° | 1.0s loop |
| Run | فخذ ±45°، ميل الجسم 8°، ذراع ±35° | 0.7s loop |
| Crouch | انخفاض 0.45م، فخذ 60°، جذع 20° | انتقال 0.2s |
| Reload | السلاح ينزل 12سم ويميل 15°، يد يسرى تتحرك للمخزن | 0.9s (AR) |
| Jump | فرد أرجل + انثناء عند الهبوط | 0.35s |

### 6.3 المزج (Blending)

```js
weight = clamp(speed / runSpeed, 0, 1);
hip.rotation.x = lerp(walkCurve(t), runCurve(t), weight);
```

- `AnimationMixer` غير متاح (لا GLTF)، لذلك منحنيات يدوية + `damp`.
- أولوية: Reload > Crouch > Run > Walk > Idle.

**معيار القبول:** فيديو/لقطات تُظهر 4 حالات مختلفة بوضوح، واختبار أن زاوية الفخذ تزيد من المشي للجري، وأن الكراوتش يخفض الكاميرا 0.45م.

**المدة:** 2-3 أسابيع (rig + 6 حالات + مزج).

### 7.1 مشكلة الآن
الأعداء 21 صندوقاً/أسطوانة. يقرأون كروبوتات، لا كجنود.

### 7.2 الحل على 3 طبقات

1. **Silhouette:** خوذة أعرض، أكتاف بحواف، حقيبة ظهر، أحزمة صدر — تمييز فوري من 50م.

3. **Team readability:** 6 ألوان تكتيكية (أزرق/أحمر/أخضر/رملي/رمادي/كحلي) مع شريط كتف + لمعة خوذة.

## 8. الأسلحة — الشكل والإحساس

### 8.1 المطلوب
1. **Viewmodel:** سبطانة أسطوانية حقيقية، جسم بثلاث طبقات (receiver + handguard + stock)، منظر خلفي (rear sight)، مشبك إصبع.
2. **Hands:** قفاز بخمسة أصابع مبسطة (5 صناديق صغيرة) بدل مكعب واحد.
3. **Materials:** 3 خرائط إجرائية (خدوش، بقع زيت، بارود) لكل سلاح بلون فريد.
4. **Effects:** وميض فوهة 3 مستويات، دخان خفيف بعد الطلقة، قذيفة تُقذف (موجودة).

### 8.2 الميزانية
- ≤ 45 mesh لكل سلاح.
- ≤ 3 مواد لكل سلاح.
- ≤ 2 lights.

**معيار القبول:** لقطة جانبية للسلاح تُظهر 5 تفاصيل مميزة (منظر، سبطانة، مخزن، مقبض، أخمص) واختبار يحصي الـmeshes تحت الحد.

**المدة:** أسبوعان.

### 9.1 المنحنى

|---|---|---|
| 1-10 | 1000/مستوى | Credits + فتح مرفقات |

الصيغة: `xpNeeded(level) = 800 + level * 120` (تصاعدي خطي بسيط، قابل للتعديل من ملف واحد).

### 9.2 المكافآت

- **Daily:** 3 تحديات (اقتل 10، العب مباراتين، افز مرة) → 300 XP.
- **Weapon mastery:** لكل سلاح 10 مستويات، تفتح مرفقات.
- **Battle pass:** 50 مستوى، مكافآت تجميلية فقط (لا pay-to-win).

### 9.3 الحفظ

`localStorage` الآن؛ عند المالتي بلاير ينتقل إلى PostgreSQL مع migrations.

**معيار القبول:** لعب مباراتين → XP يتراكم → المستوى يزيد → يُحفظ بعد reload → شاشة الترقية تظهر.
